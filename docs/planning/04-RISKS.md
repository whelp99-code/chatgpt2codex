## R3 이상 실패 모드

```
Risk ID: R-11 — 이력 쓰기 실패가 세션 정리를 중단시킨다
Trigger:
  디스크 가득 참, 상태 디렉터리 권한 변경, 파일시스템 읽기 전용 전환 중 하나가 발생한 상태에서
  sweepInterval이 돌아 SessionHistory.record()가 예외를 던진다.
Failure:
  예외가 setInterval 콜백 밖으로 전파되면 그 tick의 나머지 작업이 실행되지 않는다.
  sweepSessions는 이미 끝났더라도, 이후 tick에서 같은 예외가 반복되면 정리 경로가 사실상 멈춘다.
  결과적으로 닫힌 대화창의 full-write 리스가 남아 소유자가 자기 프로젝트를 편집하지 못한다
  (PROJECT_LOCKED). 이것이 v2 세션 맵이 애초에 해결하려던 문제의 재발이다.
Detection:
  겉으로는 "왜 내 프로젝트가 잠겨 있지?"로만 보인다. 대시보드에는 죽은 세션이 살아있는 것처럼
  남아 있어 원인 추적이 어렵다. 그래서 D=4.
Recovery:
  즉시: 서버 재시작 — 시작 시 sweepSessions(null)이 모든 세션을 지운다.
  근본: record()를 절대 던지지 않게 만든다.
예방 (구현 강제 사항):
  1. SessionHistory.record()는 내부에서 모든 예외를 잡고 아무것도 던지지 않는다.
  2. 호출부는 그 위에 한 번 더 방어한다: `record(...).catch(() => undefined)`.
  3. 순서를 지킨다 — sweepSessions로 세션을 먼저 정리하고, 그 다음에 이력을 기록한다.
     이력이 실패해도 정리는 이미 끝나 있다.
  4. ACCEPT-HIST-002가 이 동작을 검사한다 (쓰기 불가 상태에서 세션은 정상 제거).
```

## R2 항목의 처리 방침

```
Risk ID: R-04 — stdio 세션이 항상 "대기"로 보인다
상황: Codex CLI, 상태바, serve --stdio는 STDIO_SESSION_KEY를 쓰며 HTTP 전송 계층의
      sessions Map에 존재하지 않는다 (CONFIRMED: types.ts:65-66 주석).
방침: 활동 시각 조회를 2단계로 한다 — 주입된 Map에 있으면 그 값을, 없으면 store의
      lastActiveAtMs를 쓴다. stdio 세션은 정확도가 떨어지지만 "영원히 대기"는 면한다.
      이 폴백은 ADR-001의 롤백 경로와 같은 코드라 추가 비용이 없다.
```

```
Risk ID: R-05 — 시작 시 sweep이 가짜 완료를 만든다
방침: ADR-004대로 http.ts:415(시작 시)에는 이력 기록을 붙이지 않고, http.ts:427(주기 sweep)에만
      붙인다. 두 호출을 구분하는 것은 코드 위치이므로 실행 에이전트가 혼동하지 않도록
      PR-003의 SUB에 행 번호와 함께 명시한다.
```

```
Risk ID: R-09 — 구버전 피어 응답
방침: fetchPeerStatus가 받은 JSON에 status/history가 없을 때를 기본값으로 흡수한다.
      피어를 업그레이드하도록 강제하지 않는다 — 맥과 우분투의 빌드 시점이 다를 수 있다는 것이
      이미 확인된 사실이다(우분투 빌드에 instance-name.txt 지원이 없었던 전례).
```

## 필수 검토 목록 점검

| 항목 | 판정 |
|---|---|
| 인증 우회 | 해당 없음 — 새 라우트를 만들지 않고 기존 requireOwner 뒤에만 붙인다 |
| 권한 상승 | 해당 없음 — 리스 권한 체계를 건드리지 않는다 |
| Injection | 해당 없음 — SQL·셸 명령을 구성하지 않는다 |
| XSS | R-07로 관리. 기존 esc() 사용 강제 |
| CSRF | 해당 없음 — 상태를 바꾸는 요청을 추가하지 않는다 (GET만) |
| SSRF | 해당 없음 — 피어 URL은 기존 peers.txt 경로 그대로 |
| Secret 노출 | 이력에 토큰·경로·명령을 기록하지 않는다 (03 문서 4.2) |
| 동시성 충돌 | R-01, R-11로 관리 |
| 부분 저장 | 이력 재작성 중 중단 시 일부 유실 — ADR-003에서 수용 근거 기록 |
| 데이터 손실 | 이력은 표시용이며 감사 기록(audit.jsonl)은 건드리지 않는다 |
| Migration 실패 | Migration 없음 — sessions.json 스키마를 바꾸지 않는다 |
| 외부 API 실패 | 피어 조회 실패는 기존 InstanceError 경로 그대로 |
| 기존 기능 회귀 | R-03, R-10으로 관리. Baseline 463 테스트가 회귀 감지선 |
